# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- **An AI assistant that edits your files, with every change undoable.** A dock beside the document, opened with `Ctrl+Alt+A` and off by default. You ask for something in your own words - fix this paragraph, pull the dates out, do the same to the other eleven notes - and it makes the change. It works across files, not just the one you are looking at, and it has seen the file you currently have open along with any selection. Set it up under **Settings > AI assistant**: pick a provider, paste your key, press **Fetch**, choose from the models your key actually reaches. Providers are OpenAI, Anthropic, Gemini, and locally Ollama and LM Studio.

  Every file it touches is listed in the panel with its own **Undo**. It will not write a file it could not fully edit - if one of its changes does not match the text, that file is skipped and the reason is shown rather than a half-finished rewrite landing and looking like it worked. If you have edited a file by hand since it was read, it skips that file too, so it cannot quietly undo your work.

  The model is asked to quote the text it wants to change and say what should replace it, rather than to call tools. That is what makes a change reviewable: it can only make a change you could have made with search and replace, and it cannot invent a step nobody asked for. Your API key is stored encrypted in your operating system's keychain, never in `config.json`, and the interface has no way to read it back. It refuses to send a key over unencrypted `http://` to a remote host; a keyless local server on your network still works, so local models are unaffected.

- The document title moved inside the editor, above the first line, Obsidian style. It used to live in a header bar pinned to the top of the window, which put a second copy of the name away from the writing and left nothing in the document to orient by. It now renders as part of the document, so it scrolls away with the content, sized large and in body text colour so it reads as the note's name rather than as the first heading of its content, with clear space before line 1. The header keeps the reading toggle and the menu. Source mode shows raw markdown, so the title is hidden there.
- A **File Path** setting in Editor hides the path on the left of the document footer, for people who do not need it.
- The sidebar's quick actions moved to the top edge and left-aligned, with the search field below them spanning the full width, so the buttons you reach for to start something take the top and search follows. Sidebar spacing now follows a 4px scale with the internal-space-no-larger-than-external rule. **Collapsing the panel keeps Settings and your folders reachable.** The 48px strip held only the expand button, so hiding the panel hid the control people reach for most and every tab group vanished with it, leaving a bare strip beside a document you cannot get back into. Settings now sits at the bottom of the strip and each group keeps its icon down the middle, in the same order and with the same glyphs the expanded panel uses. The list scrolls rather than compressing, so a vault with many folders does not squeeze them into unreadable slivers. Clicking a folder icon reopens the panel on that group, and opens the group if it was shut; the document you were reading is left alone, since the click asked for a folder and not for an edit to steal focus.
- **Open file draws a document instead of a folder.** It sat beside New group's folder-plus in a three-button row, so two of the three read as the same shape, and it was wrong on its own terms: the dialog picks one markdown file, not a folder. New group is now the only folder in the row, being the one action there that makes one. The welcome screen's Open file button matches.
- Background **effects** now match the reference implementation. Dither preserves the source colours instead of collapsing to black and white, ASCII draws from a bitmap glyph set and keeps the artwork's colours rather than painting grey blocks, Halftone is alpha-aware so transparent regions read as paper, and Scanlines inverts on light themes instead of only darkening. Every effect reworks itself when the theme flips, and the rendered result is cached per effect and scheme so switching back is instant.
- **New group** in the sidebar's quick actions creates a tab group in one click, with the label focused and pre-selected so it can be typed straight away. Vertical mode previously offered grouping only through a tab's context menu, and horizontal mode through a small toolbar icon.
- **Drag a document onto a folder to file it away.** The gesture was already computed and already worked, but nothing showed it was happening: hovering a folder row painted the same solid outline as hovering a gap between two rows, so "into this folder" and "insert here" looked identical and the only way to find out was to drop and check. A hovered folder now fills and takes a dashed accent outline in both tab layouts, kept deliberately distinct from the solid insertion outline.

### Changed

- **Preview an export before you write it.** Exporting went straight from the note menu to a save dialog, so page size, margin and theme were set in Settings, trusted, and only discovered to be wrong once the file was on disk. The pane's Preview tab renders the open document at real page dimensions with those three controls above it, and Save PDF / Save HTML write what is on screen. The preview goes through the same `renderExportHtml` the exporter writes to disk - it was moved into `shared/` for exactly this - so the two cannot drift. A long note grows past one page with a guide at each break rather than being clipped; the PDF still paginates on its own, so the guides are indicative and the footer says so. The controls wrap onto a second row in a narrow pane rather than squeezing, because a clipped Save button is one the user cannot tell they have.
- **The second pane is tabbed.** Surfaces used to be reached through a picker inside the pane, so changing one meant going back to the picker first and choosing again - four copies of the same "back to surfaces" header, one per surface, all existing only to get you back to that menu. Files, Backlinks and Document are tabs now, each one click from every other, and the pane opens on Files rather than on a menu. The Document tab opens the file picker when nothing is open, which is what the picker's row used to do. The launcher is gone. All four tabs have a shortcut - `Ctrl+Shift+E`, `Ctrl+Shift+B`, `Ctrl+Shift+D` and `Ctrl+Shift+P` - so a surface is one keystroke away instead of a click and a glance.
- **The document surface had two header rows and two close buttons.** With the tab strip added above it, the document bar kept its own header underneath, so opening a second document stacked a bar of tabs over a bar of controls with an ✕ on each. The reading toggle and the document menu now sit in the tab strip beside the pane's single close, and the bar contributes nothing but its own controls. The strip carries no rule and no underline on the active tab - selection is weight and colour, matching the panel headers below it - and its text is 13px, the size every panel row already used.
- Tab groups carry an icon instead of a colour. Every group row ended in a bright dot that competed with the notes it was meant to label, and a dot cannot say what a group is for. The group menu now opens a grid of icon presets, the same grid in both tab layouts, and the choice is saved per group and shown on the row, on a "Move to" entry, and on the group while it is being dragged. New groups start on the folder pair they already used, so nothing moves until you pick something. Groups saved by an older build keep working: their colour is dropped and they draw the folder pair.
- Group rows now match note text and icon sizes in both tab layouts. Open and closed folder icons replace the small arrows, so the label sits where the note labels do.
- Word and character counts and the mode button moved from a floating box in each pane's bottom-right corner to a full-width footer beneath the document, and the file path moved down to the left of that footer. The box sat on top of the last line and had room for itself only in wide panes. The footer draws no rule: the document fades out as it reaches the bar, so nothing separates the two. Scrolled to the end of a document, the final line stays clear of the fade and reads normally. The bar is a material layer like the pane and the title bar, so it follows the translucency, surface blur, and window material the user picked instead of carrying its own opacity. Each split pane shows its own path, counts, and mode control.
- Opening and closing the second split pane now use the sidebar's 180ms width animation and easing. Both panes resize together, and reduced motion keeps the change instant.
- Release notes moved from one file per version under `docs/release-notes/` to a single `CHANGELOG.md` in Keep a Changelog form, matching the format used upstream. The What's new dialog and the update hover card read the new file; nothing else changed for users.
- Background artwork is stored as **JPEG** unless the decoded image has transparency. Re-encoding a photograph as PNG inflated it past 13 MB for a 2560px wallpaper, which was then base64ed across the process bridge on every launch. PNG is kept only where transparency has to survive, and PNG assets written before this change still load.

### Fixed

- **Line Numbers Walked Off Their Lines After a Font Change**: Editor font size and line height are CSS custom properties, so changing either resized the text without the editor view hearing about it. CodeMirror kept its cached line heights and the gutter kept the offset it had measured, so the numbers stayed on the old line pitch and drifted away from the text they labelled, by up to 54px at 12px/1.2 and 91px at 20px/2.0. A cold start at the same settings was always fine, which is why it only showed up after changing the setting in place. Both metrics now trigger a re-measure of the live views.
- **The top bar could not be dragged.** The compact document header fills the middle of the title bar and opted its whole host out of the window-drag region, so every blank part of it was dead to the mouse and the window could only be moved by its edges. The header is now a drag region and only the reading toggle and menu opt out, so blank space moves the window and the controls still take clicks. The header is not a drag region in horizontal tabs, where it sits in the document panel and would otherwise take text selection away.
- **The inline title swallowed every keystroke.** The widget told CodeMirror to keep handling events aimed at it, so clicking the title put the caret in the document and typing went there instead. The title now accepts typing, and Rename from the document menu still focuses it.
- **Line numbers sat above their line.** CodeMirror sizes each gutter element to the whole line block, which for a heading is far taller than the digits, so a top-aligned number read as belonging to the line above. Numbers are now centred in their line box. The pinned and unpinned rule in the sidebar is gone; those sections are separated by their order alone.
- **Dropping a document onto the folder it was already in moved it to the bottom of that folder.** The folder row counted as a target regardless of where the document came from, and it resolved to "into this folder, at the end" - so hovering your own folder silently reordered the document. A folder is no longer a drop target for its own members; the row falls back to normal reordering among its siblings, where dropping above or below a sibling still does what it says.
- **A document dropped into a closed folder disappeared.** A closed folder renders no rows, so the document was filed somewhere with no rows and no way to see it had landed. The folder now opens itself after the drop. It does not open while you hover, on purpose: the drag holds a snapshot of row positions from the moment the gesture started and deliberately refuses to re-measure mid-drag, so growing the list underneath the pointer would leave every insertion marker pointing at the wrong row.
- **Hiding the file path dragged the word counts to the left edge.** The footer spaced its two groups apart with `space-between`, so with the path removed the counts became the only child and landed at the start instead of the end.
- Haze backgrounds now match MonoCode's sharp upper image, progressive blur, fine line texture, and earlier fade. Content views use a shorter fade, and settings previews scale the blur to their size.
- Changing the theme left the background effect rendering for the previous scheme until the next effect change.
- Settings subscribers were notified before the new values reached the DOM, so anything reading a resolved value such as `data-colorScheme` saw the previous theme. `set` now applies to the DOM before notifying, matching `setMany`.

### Removed

- **The AI assistant is gone.** WriteMd is now a markdown editor and nothing else: no chat panel, no model picker, no streaming replies, no in-place edits from a model, no chat history, no attachments, no web-search grounding, and no API key to manage. Every part of it went: the panel and the session controller that owned it, the OpenCode CLI integration and the managed server it started, the OpenAI/Anthropic/Gemini/Mistral/Groq/DeepSeek/xAI/OpenRouter/Nvidia/Ollama provider adapters, chat-session persistence on disk, the `Ai Assistant` settings tab, the `Ctrl+Alt+A` shortcut, the sidebar and surface-launcher entries, and the `ai.*` settings block. API keys are no longer read, encrypted, or written anywhere, and the app makes no network requests except the update check. The second pane keeps its files, backlinks, and second-document surfaces; the background's **Show behind** control loses its AI-pane option, which was the only other thing it had. Saved settings keep working: unknown `ai.*` keys and a stored `appearance.backgroundTarget` of `ai` are ignored rather than rejected, so nothing needs migrating by hand.

## [1.4.0] - 2026-10-08

### Added

- **Tab Dragging, Reordering, Grouping, and Pinning**: Tabs could not be dragged at all, so ordering, pinning, and grouping were all separate concepts with separate code. Both tab layouts now share one drag controller with stable tab identities instead of array indices, so unpinning moves the right tab and canceling a drag leaves order unchanged. Drops resolve to explicit before/after neighbor IDs rather than an insertion gap that read as a final index, edge scrolling continues while dragging, and keyboard reordering works the same in both orientations.
- **A Flatter Workspace**: The editor sat inside its own rounded frame with a 5px outer gutter, so the document header, window controls, and editor surface read as three separate bands and the sidebar floated apart from the theme. The inner frame and gutter are gone. Document headers and caption controls paint the shared editor surface, the sidebar uses the theme secondary surface, titles stay centered on the full header, and paths are visible again. Sidebar and split dividers expose three-dot handles with the same pointer and keyboard resizing as before.
- **Vertical Tabs by Default**: Open notes, pinned notes, and groups lived in different places depending on orientation, and existing profiles had no path from one to the other. Both orientations now share the sidebar, with a 48px by 1px theme-colored line separating pinned or grouped notes from unpinned ones when both sections exist. Existing profiles switch to vertical once when the workspace migration runs, and later explicit orientation choices are retained. Horizontal tabs remain under Appearance.
- **A Welcome Screen Inside the Shell**: Home bypassed `Shell` with its own toolbar, caption buttons, rounded frame, fixed columns, and watermark, so opening or closing a note rebuilt the whole window and every screen had its own menu behavior. Home now occupies the same content slot as the editor, with the sidebar, captions, and settings entry staying mounted. It offers New note, Open file, four recent notes with short paths and full-path tooltips, and vault access, adapts to short windows and both orientations, and survives a canceled picker or a failed file read instead of stranding the window.
- **Local Image Backgrounds**: There was no way to put artwork behind the workspace or AI panel. Imported images are copied into app-owned storage under validated IDs and rendered pane-local beneath content rather than behind translucent panels and the rail, so importing leaves surface opacity unchanged and removing a background leaves the source file alone. Visibility covers empty views or all views with separate empty and content strengths, effects run off the UI thread with cached results, and blur, surface opacity, and window material stay independent controls.
- **Reorganized Settings**: Search sat in the title bar and forwarded into settings, categories had grown without grouping, and fixed choices used native controls that ignored the theme. Search now lives in the settings sidebar with the same inset as the document sidebar and focuses through Shadow DOM on open. Writing groups New notes, Editor, and Files and vault; Workspace groups Appearance and Keyboard shortcuts; Application groups AI Assistant, Advanced, and About WriteMd. All fixed choices use themed dropdowns with keyboard selection and Escape handling, and the New Design beta card plus the classic-layout switch are removed.
- **Locally Bundled Fonts**: The remote font stylesheet conflicted with CSP and every launch depended on the network for type. Inter, Manrope, DM Sans, Space Grotesk, JetBrains Mono, and Geist Mono now load locally with no remote requests. Removed serif and handwritten choices migrate to Manrope while preserving size and other editor preferences.
- **Actions for Each Split Pane**: The second document had no header of its own, so mode changes, rename, move, export, and find all resolved through the active tab and the pane could not be closed on its own. The secondary pane now uses the shared document header with its own path, title, reading toggle, menu, and close action, and every one of those operations targets the selected pane. Find keeps its pane when the search field takes focus.
- **Updates in the Vertical Sidebar**: Vertical mode had no update surface at all. Available updates now appear above AI Assistant with download progress and Restart to update through the same typed updater bridge, while horizontal mode keeps its toolbar control.

### Fixed

- **Closing a Group Dropped Unsaved Edits**: Deleting a tab group with `closeTabs` filtered tabs by group and rebuilt state without asking, so dirty members vanished silently. It now checks for dirty members first, confirms, keeps the autosave timer consistent on cancel, resolves the surviving active tab by stable ID, and unwatches only paths no remaining tab still holds.
- **Deleting a Dirty File Wrote It Back**: Pane teardown and queued autosaves raced the delete, so removing a file while a save was in flight recreated it on disk. Deletes now mark the path, drain pending writes for it, clear both pane timers, refuse writes tagged for a deleting path, and only then remove tabs, watchers, and conflict state. A failed delete restores the timers instead of leaving autosave off.
- **Configured AI Panels Lost Their Backgrounds**: The empty AI state rendered the shared background element but the configured chat view never mounted one, so setting a panel image changed nothing once a session existed. The chat view now mounts `<writemd-background target="ai">` with empty state derived from message count, so empty and content strengths apply in both states.
- **Document and Text Menus Clipped and Stacked**: The document menu assumed a 230px width while rendering wider contents and positioned itself inside the toolbar containing block, so short windows clipped its actions. It now uses the shared context-menu adapter anchored to the actual button with measured width, viewport edge padding, and height constraints, and document and text menus dismiss one another through the event bus. Submenus render SVG chevrons, support arrow-key entry and exit, wait for the popup before taking focus, and restore focus on close.
- **Toolbar and Editor Split at Reduced Opacity**: The toolbar and panel shared a CSS color but the workspace painted another translucent surface behind the panel, so at 65% opacity the two rendered different colors and captions kept a mismatched dark box with a visible border. The workspace now stays transparent except for its resize gutter, both surfaces derive from the same token, and caption buttons share the editor surface with no box or rules.
- **A Rename Moved the Save Target Under You**: Renaming or moving a file updated the tab but left the split pane, watchers, and persisted paths pointing at the old location, so the next save wrote to the old path or over an intervening external edit. Every open reference now retargets on rename or move, including the secondary document, file watchers, and persisted paths, without touching intervening edits.
- **Find Switched Panes on Focus**: Focusing the find field re-resolved the target to the active tab, so searching the secondary pane jumped back to the primary. Find now retains its pane when the input takes focus.
- **Drag Cancellation Committed an Order Change**: Canceled gestures still called the tab transaction, and pin or group changes resolved through shifting array indices. Canceled gestures never reach the transaction now, all moves go through stable-ID `dropTab` with removal preceding neighbor resolution, and the library AutoScroller keeps edge scrolling alive while selection reveal skips active gestures.
- **Narrow Windows Overflowed and the Rail Jumped**: Two panes each demanded their minimums past the window width, rapid sidebar toggles settled at the wrong size, and the rail fade held width before jumping. Panes now use measured allocation with derived pixel limits and a compact surface below the breakpoint, and rail motion animates allocated width with retargeting on toggles.
- **Reset Left Orientation and Motion Stale**: Resetting settings wrote defaults but never notified every subscriber, so orientation and motion kept their old values until restart, and queued saves could land an older snapshot over a newer one. Every registered subscription is notified on reset, saves keep the newest snapshot, and a failed save reports honestly and can be retried.
- **AI Session and Stream State Leaked Across Layout**: Session and stream ownership lived with editor layout, and OpenCode stream events were unfiltered, so one session pumped events into another. Ownership now sits in `AiSessionController` separate from layout, and stream events are filtered to the requested session.
- **A Canceled Picker Emptied the Window**: Canceling the file picker or hitting an unreadable file left welcome visibility to whatever the opener had set, which could leave no home and no document. File opening now leaves visibility to the file-state subscription, so home stays put in both cases.

## [1.3.0] - 2026-10-05

### Added

- **A Draggable Table Toolbar**: The floating toolbar above a table is anchored by CodeMirror and could not be moved, which put it over the document title on a short table and outside the reading column on a wide one. A grip at its head drags it, and so does a press anywhere on the bar that then travels - the decision is on movement rather than on which element was hit, so grabbing it by a button works like grabbing the grip, and a press that does not move stays a click on whatever was under it. The click a drag would otherwise produce is swallowed, so moving the toolbar cannot insert a row as a side effect. Double-click sends it back where CodeMirror anchored it. The offset is kept per editor, so the two split panes hold separate positions, and the last one is saved so it survives a restart.
- **A Note in a New Vault**: On the first launch, where the vault did not exist until that launch created it, WriteMd writes one `Welcome.md` into it. It skips Markdown basics on the assumption that anyone opening a markdown editor knows them, and shows instead what this editor does on its own: tables that edit in place, the toolbar above them, math and Mermaid, task lists, footnotes, and where files actually live. An existing vault is never seeded, including an empty one - someone who emptied a folder did that on purpose, and a file reappearing overnight is the thing this app exists to avoid. Repointing the vault in Settings does not seed either.
- **OpenCode Provider (Console Login)**: OpenCode joins the provider list and works like every other one - pick it in Settings → AI Assistant, chat in the panel, same streaming, stop button, attachments, and `writemd-replace` edits. No API key: WriteMd finds your CLI (including npm shims), starts its own `opencode serve` on a loopback port at first chat, and stops it on quit, using your CLI's Console login for auth. Models are your CLI's (`provider/model` free text with Fetch listing `opencode models`). The status row shows binary, version, login state, Browse/Recheck, and a diagnostics box that prints every failed probe when detection misses, so a miss is debuggable instead of silent. Agent models that emit tool-call markup get a no-tools instruction plus output stripping, since sessions run with tools denied.
- **Nvidia Provider**: NIM's OpenAI-compatible endpoint (`integrate.api.nvidia.com`) with Bearer auth. Key from build.nvidia.com, Fetch lists the catalog, model IDs in `org/model` form.
- **Keyless Web Search**: A globe toggle in the composer and a switch in Settings ground answers with a DuckDuckGo search before sending, for any provider. Results arrive as cited sources with links; the model is instructed to treat them as opened pages and never talk about its tools. The search itself is silent - no extra Thought line per prompt.
- **Settings Shell**: Settings is a full screen with a Back button bottom-left, native-feel minimize/maximize/close top-right, all in theme variables.
- **Settings Search Finds Settings**: Search matches the setting you name, not just the section that shares a word with it, jumps to the section that holds it, marks every matching row, and scrolls the first one into view. Typing `auto save` lands on Auto-save under Files & Vault, which is where it lives. Enter and the arrow keys step through matches, the sidebar filters to sections with hits (group headers included), and the count sits under the box.
- **Auto-Hiding Scrollbars**: Scrollbar thumbs stay invisible until you scroll a pane, then fade out when it goes idle. Every pane is covered, including the ones inside shadow DOM, where a document-level listener cannot see the scroll at all.
- **In-Place Table Cell Editing**: Clicking a table cell in live preview edits that cell where it stands - Enter moves down a row, Tab moves across, Escape cancels, clicking away commits. The table never collapses to source pipes; raw editing stays in source mode. Keystrokes are shielded from the editor core in capture phase so Ctrl+A selects cell text and Enter commits instead of acting on the whole document.
- **Motion You Can Actually See**: Settings → Appearance → Animation, with three choices: Match system, Always animate, Never animate. Windows with "Animation effects" turned off reports `prefers-reduced-motion: reduce`, and every animation, transition and staged AI text reveal in the app switched itself off with nothing on screen to say why. The preference is resolved once at startup onto `<html>` as `data-motion`, every animated surface tests that instead of the media query, and the split-pane WAAPI animation plus the word-by-word answer reveal follow it as well.
- **One Motion System**: Motion is no longer a per-component decision. Durations, easings and the press scale live in one set of tokens in `global.css` (`--motion-instant` through `--motion-slower`, `--motion-ease*`, `--motion-press-scale`), and every scripted animation goes through a single `animate()` in `utils/motion.ts` with `slideIn`/`slideOut`/`reveal`/`conceal` on top of it. Entrances ease out, exits ease in and are shorter, and nothing overshoots: a pane that bounces past its resting width reads as a glitch, not as motion. Menus, dialogs, panes, notices and the AI panel all read the same numbers.
- **Panes Actually Move**: The tab rail was mounted and unmounted outright, so collapsing it was an instant disappearance; it now slides out with the space closing behind it and slides back in on expand. Closing the split view fades the pane out before the left pane claims the width, instead of both happening in the same frame. Opening the split no longer bounces: a WAAPI animation was driving `flex-basis` at the same time as the stylesheet's `transition: flex`, which snapped the left pane back out to full width on the first frame before easing it in. Buttons press with a scale rather than only a colour change.
- **Big Notes Stay Responsive**: Work that scaled with the file is gone or bounded. Word count is a single debounced pass instead of one per keystroke, the editor no longer builds a second copy of the document to compare it against itself, live preview and wiki-link decorations only walk the visible viewport, math delimiters scan incrementally with a margin, and the find count stops at 5,000 matches. Live-preview tables patch rows in place instead of rebuilding, and render at most 400 rows with a notice saying what was left out. The file tree lists 300 rows before offering "show more", backlinks read at most 24 files at a time, the AI context is capped at 200 KB, and PDF/DOCX export refuses anything over 4 MB and points at HTML export rather than failing silently.
- **Stress Harness**: `tests/stress/` generates a synthetic vault (a 1,500-note tree, a 600-row table, a 6 MB note, long-line, math, Mermaid and wiki-link fixtures), measures the editor against it, and fails if a size guard regresses. `tests/e2e/stress.spec.ts` drives the same vault through the UI. Measured before/after numbers are in `docs/stress-report.md`, including the limits that remain (a 200,000-line first parse, 4 MB preview caps).

### Changed

- Documentation moved to `docs/`: `PRD.md`, `phases.md`, `AI_PANEL_WORKLOG.md` and `zen-animations-overview.md` were sitting in the repository root next to the build config, and every reference is updated.
- README screenshots live in `docs/screenshots/` with descriptive filenames and alt text that describes what is on screen, instead of pointing into the `_assets/` folder WriteMd itself creates for pasted images.

### Fixed

- **Clicking a Table Cell Rewrote Its Markdown**: A cell commit compared the cell's rendered text against its source, and for any cell markdown-it had parsed the two differed. Clicking a cell holding `**bold**` and clicking away again - no typing - committed `bold` over `**bold**`, and a link lost its URL. Cells whose source is not their own displayed text now edit their source instead, and a commit with an unchanged cell writes nothing at all.
- **A Pipe Typed Into a Cell Broke the Table**: A pipe was written raw where the renderer reads one as a column break, so `a|b` in a two-column table produced three cells with the third invisible, and an escaped `\|` was not understood at all. Pipes are escaped on write, and the split only breaks on unescaped ones.
- **Undo Crossed Files**: One view serves every tab, so its single undo stack accumulated every file's edits. Opening a note and pressing Ctrl+Z applied the previous note's inverse change to the new one - in a freshly opened one-line note that appended a table cell from three documents ago, and autosaved it. A document swap now replaces the editor state, which is a boundary undo cannot cross.
- **A Merge Could Land on the Wrong File**: Accept and Reject both resolve through the active tab, so switching tabs while a merge was open put one file's merge on another. Tab switches are refused during a merge, the commit checks the tab is still the one under merge, and a conflict raised against the split pane merges the pane instead of the tab.
- **The OpenCode Port Was Handed to the Renderer**: `opencode serve` is unauthenticated - a loopback bind and an ephemeral port were the only things protecting it - and every Settings recheck passed that port to the renderer. The renderer never read it; it is off the bridge.
- **A UNC Path Could Be Executed**: `ai.opencodeCliPath` was validated on basename alone, so a `\\server\share` path passed the check and was then run with the user's privileges. It now has to be an absolute local path.
- **A Note Over 64 KB Could Lose Its Top**: The frontmatter scanner tested its 64 KB window for a closing delimiter, so a note longer than that could have its first 64 KB replaced by a Properties card.
- **Split View Swallowed Edits**: The secondary pane's keystrokes reached neither the primary tab nor the disk, because auto-save and save are both scoped to the active tab. Same-file edits now mirror into the tab, a different file in the split pane gets its own debounce, manual save flushes it, and closing the pane writes it instead of dropping it. Opening another file in the pane now confirms the outgoing document rather than dropping it silently, and the pane's file is watched so the new autosave cannot overwrite an external edit.
- **Split Pane Edits Landed at the Top of the Document**: Clicking in the secondary pane put the caret where you pointed but left the editor's own selection behind, so Enter, Backspace and the arrow keys all acted on position 0. Two causes, both about focus: the split pane's wrapper is slotted into `<writemd-panel>`, and CodeMirror had adopted that panel's shadow root as the view root, which reports no active element here and so skipped every caret write; and `hasFocus` also insisted on `document.hasFocus()`, which Windows does not always grant. Both views now get the editor's own shadow root as their root, and a view that is the active element of the root containing it counts as focused.
- **Wiki Links Could Not Be Clicked**: Clicking a `[[wiki link]]` in live preview did nothing, because the link widget's `ignoreEvent` claimed clicks aimed at decorations but returned true for the text itself, which is exactly where the click lands.
- **Accept and Reject Did Not Reach the File**: Resolving an external-changes diff updated the editor and left the file on disk untouched. Accept dispatches no document change at all (CodeMirror only retargets the original document), so the listener never fired; both buttons now write immediately instead of waiting on an auto-save debounce that may be off.
- **Settings Search Found Nothing Unvisited**: Matching read only the rendered panel, so `vertical` (an Appearance setting) matched nothing from General. Search now carries a row index, which also fixed `auto save` routing to Editor, where no such setting exists.
- **Windows CLI Spawning Mangled Quotes**: Quoted program paths through spawn argv get backslash-escaped by Node, which `cmd.exe` reads literally. All CLI calls now go through PowerShell's `& 'path'` call operator; the serve child is reaped by tree-kill on quit.
- **Fetch Lost Models**: `models --format json` can succeed with a partial shape while plain `models` holds the full list (or vice versa). Both are now read and unioned, including provider-sectioned plain text.
- **System Prompt Rewritten Around Outcomes**: The default prompt is organized by branch (file edits, file tracking, web search) instead of a warning list, and says what good output looks like rather than what goes wrong.
- **Stale Custom Binary Accepted Blindly**: A Browse pick pointing at another tool's shim could masquerade as the CLI. Non-`opencode` picks are skipped loudly.
- **Smaller Fixes**: The math delimiter cache was a module global, so in split view whichever pane was not scanned last re-read the whole document on every arrow key; it is keyed by document now. `focus-reporting` referenced the `ShadowRoot` global unguarded, which throws wherever it is undefined and took the whole focus check with it. Scrollbar roots were held in a strong Set, pinning every shadow root the app ever created. `appearance.motion` accepted any string. PDF and DOCX export skipped the fsync and the file-mode carry-over that note writes do. OpenCode's cached sessions survived a server restart, its stream kept pumping after the prompt failed, and its version gate compared `v2.3.1` unparsed and refused to start. Three stale test expectations (the old `dark` default, the removed settings X button, the 230px sidebar) were updated.

## [1.2.0] - 2026-10-02

### Added

- **One Icon Set**: The 74 hand-pasted inline SVGs are replaced by a single 64-glyph module. The same glyph used to be drawn on grids of 8 through 22 at stroke widths from 1.2 to 3, and only 2 of the 74 set round caps, which is why parts of the interface looked heavier than others. Icons now come from Line Awesome by Icons8 (MIT), with the AI glyph from their `nrk_ai-solid-expressive` set, chosen by measuring each candidate against the rest. Menus and the toolbar draw from the same table, so they cannot drift apart again.
- **Quicker Tab Strip**: The strip scrolls instead of clipping tabs past the window edge, reveals the active tab after the node is replaced, and only shows a close button on the tab you are in. Inactive tabs reveal theirs on hover.
- **Editable AI System Prompt Validation**: The prompt and settings that reach the model are now validated against the schema rather than written and ignored.
- **The AI Assistant Panel**: Chat tab, streaming replies (token by token, every provider), a composer that grows with its draft, attachments (dialog or drag & drop), and per-document transcript history. See `docs/AI_PANEL_WORKLOG.md` for the full detail.
- **Working Settings Toggles**: Auto-save, line numbers, and word wrap were drawn in Settings but read by nothing, so three visible switches did nothing. They are wired through, along with highlight-active-line, tab size, and Mermaid. Speculative controls with no reader were removed rather than left dead.
- **Menus and Dialogs Animate In**: The model dropdown, chat history, context menu, and document menu scale/fade from their anchor corner; the command palette slides in under a fading scrim; the settings dialog pops in. Buttons compress slightly on press. A split pane eases open instead of snapping. All of it is disabled under `prefers-reduced-motion`.

### Fixed

- **The AI Assistant Panel**: Reasoning-model answers no longer come back empty (`content: null` with text in a `reasoning` field is read too), and gateway error objects in an SSE frame now surface as errors instead of a silent empty delta.
- **Outside Click Closes Popovers**: The model dropdown and the chat history list no longer require clicking their icon again to dismiss - a click anywhere outside the popover closes it.
- **Attachments Actually Read Now**: The handler for `file:read-attachment` was missing from a stale build. It ships in the installer now, and dropped files ring the accent border and attach like picked ones through the same size and type guards.
- **Internal Links Did Nothing**: `[text](notes/other.md)` was handed to the OS shell, which refuses non-web schemes, so clicking a relative link in a document was a silent no-op. Link destinations now resolve against the linking document and open as a tab. Source mode matches the syntax tree as a fallback, because it renders no decorations to match against.
- **Conflict Merge Restored the Losing Version**: Resolving a conflict wrote the merged text only to a mirror, never the active tab, so closing the split brought the pre-merge content back and the next save overwrote the merge.
- **The AI API Key No Longer Crosses the Bridge**: Settings now reports whether a key is set and whether it can be decrypted, and substitutes the stored key at request time. Previously the plaintext key was readable from the renderer.
- **Settings No Longer Wipe the Saved Key**: A decrypt failure discarded the stored key and reported success. Writes are now atomic, serialized, and report failure honestly.
- **Three Hardcoded Colours and a Third Surface**: The editor shell painted a background that its own gutter exposed, so the window showed three bands instead of two. All colours across the seven themes are now derived from per-theme seeds.
- **Sandboxed Renderer**: `sandbox: true` was disabled because the preload bridge could not resolve in a sandboxed context. The bridge was simplified, the hidden export window got the same navigation guards as the main window, and permission requests are denied by default.
- **Path and Write Guards**: `save-image` writes atomically, exports validate the path they are handed, the vault path is checked rather than trusted, the vault tree walk has a depth cap against symlink loops, and a dead file watcher now throws instead of looking alive.
- **Registry Writes on Every Launch**: A packaged build rewrote the user's file associations each time it started, through a shell string. It now uses `execFileSync` and only writes when the association is missing.
- **E2E Tests Ran Against Your Real Profile**: The specs launched without a throwaway `userData` dir, so `find.spec.ts` wrote a file into your actual vault. Every spec is now isolated, and one no longer failed whenever `ELECTRON_RUN_AS_NODE` was set in the environment.
- **Wrong PDF Margins, Missing DOCX Images, Dead Top-Bar Icons, Collapsed Horizontal Layout, Tab Close on Keyboard, and a Welcome Screen Listener Leak** were each a single cause: margin units, document-relative image embedding, click-swallowing in the window-drag region, a stretched document strip, bubbled key events on the close button, and a subscription outliving its host.
